# MCP Servers for Go Development

Recommended MCP servers to wire into Claude Code for richer Go-aware tooling. Pick **one** of the gopls options below; don't run both.

## Option A — Official gopls MCP (recommended)

Built into `gopls v0.20+`. No third-party install if you already have `gopls`.

**Install / upgrade:**

```bash
go install golang.org/x/tools/gopls@latest
gopls version    # should be v0.20+
```

**Wire into Claude Code** — add to `.mcp.json` at the project root (or `~/.claude/mcp.json` for global):

```json
{
  "mcpServers": {
    "gopls": {
      "command": "gopls",
      "args": ["mcp"]
    }
  }
}
```

**What you get** (read-only, sees saved files only):

| Tool | Purpose |
|------|---------|
| `go_context` | Workspace overview |
| `go_diagnostics` | Compile/vet errors workspace-wide |
| `go_file_diagnostics` | Same scoped to one file |
| `go_file_metadata` | Package, imports, build tags for a file |
| `go_package_api` | Public API of a package |
| `go_references` | Find usages of a symbol |
| `go_symbol_references` | Same, by symbol name |
| `go_search` | Symbol search across workspace |
| `go_rename_symbol` | Safe rename across the workspace |
| `go_workspace` | Module/workspace info |
| `go_vulncheck` | govulncheck integration |

**Attached mode** (sees unsaved buffers via HTTP+SSE) — use when running alongside an editor that holds dirty buffers:

```bash
gopls serve -mcp.listen=localhost:8092
```

```json
{
  "mcpServers": {
    "gopls": {
      "url": "http://localhost:8092/mcp"
    }
  }
}
```

## Option B — `hloiseau/mcp-gopls` (richer, third-party)

Adds tools the official MCP doesn't have yet — particularly **test/coverage tools** which are very useful for Claude.

```bash
go install github.com/hloiseau/mcp-gopls/cmd/mcp-gopls@latest
```

```json
{
  "mcpServers": {
    "gopls": {
      "command": "mcp-gopls"
    }
  }
}
```

**Extra tools beyond official:**

| Tool | Purpose |
|------|---------|
| `run_go_test` | Run `go test` for a package, return formatted results |
| `analyze_coverage` | Coverage report for a package |
| `run_go_mod_tidy` | Run `go mod tidy` and report changes |
| `run_govulncheck` | Same as official but with parsed output |
| `module_graph` | Dependency graph |
| `format_code` | Run gofmt/goimports |
| Code-actions (rename/extract/inline) | LSP refactorings |

Plus prompts: `summarize_diagnostics`, `refactor_plan`.

## What to skip

- **`Yantrio/mcp-gopls`** — author flagged it as untested ("generated by Claude with no review"). Skip.
- **Standalone playground / pkg.go.dev MCPs** — none of the published ones add value over `gopls` + WebFetch on demand.
- **govulncheck-only servers** — both gopls options above already include it.

## Choosing

| You want... | Pick |
|-------------|------|
| Simplest, official | A (`gopls mcp`) |
| Test runs and coverage as MCP tools | B (`hloiseau/mcp-gopls`) |
| Read live unsaved buffers from your editor | A in attached mode |

## Verify

After wiring up, in Claude Code:

```
/mcp                    # list connected MCP servers
```

You should see `gopls` (or whatever you named it) connected with its tools listed. Test with: "What's the public API of the `domain/entity` package?" — Claude should call the `go_package_api` tool.
